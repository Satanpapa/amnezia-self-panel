# Amnezia Panel — план разработки

> Перевод исходного implementation_plan.md. Имена протоколов, API, параметров и технических идентификаторов сохранены.

## Принятые продуктовые решения

- Полноценная панель: Rust (Axum + Tokio) backend, React + TypeScript frontend, Bash-установщик `install.sh`, CLI `amnezia-panel`, Dockerfile и docker-compose.
- Протоколы: AmneziaWG (AWG 1.5 / 2.0 / 3.x с DPI-обфускацией), WireGuard, OpenVPN и OpenVPN over Cloak.
- Автообновление: динамические URL подписок для клиентских конфигураций и обновление Docker-образов с сохранением состояния пиров.
- Интерфейс: тёмная NOC-эстетика, переключение RU / EN.

## 1. Концепция

Панель заменяет ручную настройку через SSH и разрозненные CLI-скрипты единым интерфейсом в духе 3x-ui для экосистемы Amnezia VPN. Администратор устанавливает панель на Ubuntu/Debian/Alpine, создаёт учётную запись, разворачивает изолированные контейнеры протоколов, управляет клиентами, пирами, квотами трафика и сроком доступа, настраивает DPI-параметры и выдаёт динамические ссылки подписок или QR-коды.

Ключевая ценность — отсутствие необходимости повторно рассылать статические конфигурации после изменения порта, IP, DNS или параметров обфускации. Изменение конфигурации повышает её ревизию, а клиент получает актуальный пакет при следующем обращении по ссылке подписки.

## 2. Пользовательские сценарии

### Первый запуск
- При чистой установке отображается создание администратора: имя пользователя и пароль.
- Предустановленных демонстрационных паролей нет.
- Пароль хешируется на сервере через Argon2id.
- После создания администратора первичная настройка блокируется.

### Протоколы и DPI
- Раздел контейнеров поддерживает `amnezia-awg`, `amnezia-wireguard`, `amnezia-openvpn`, `amnezia-cloak`.
- Студия AmneziaWG предоставляет проверенные пресеты и ручную настройку `Jc/Jmin/Jmax`, заполнения `S1–S4`, magic headers `H1–H4` и CPS-сигнатур `I1–I5`.
- Валидатор проверяет ограничения Amnezia, включая `S1 + 56 != S2`, `Jmin <= Jmax` и уникальность диапазонов `H1–H4`.

### Клиенты и пиры
- Для WireGuard/AmneziaWG генерируется пара Curve25519; для OpenVPN/Cloak — сертификаты и UID.
- Клиенту назначается свободный IP в подсети, задаются лимит трафика и дата окончания доступа; доступ можно включать и отключать.
- Форматы выдачи: динамическая HTTPS-ссылка подписки, URI `vpn://`, QR-код SVG, JSON bundle `.vpn`, конфигурация `.conf` или `.ovpn`.

### Обновления и развёртывание
- Экран обновлений показывает текущий и upstream digest Docker-образов `amneziavpn/*`, расписание и журнал обновлений.
- VPS Deploy & CLI предоставляет команду установки, справку CLI, SSL через Certbot/ACME и файлы развёртывания.

## 4. Архитектура

### Backend и runtime
- Основной backend: Rust + Axum + Tokio. Frontend остаётся на React + TypeScript.
- SQLite подключается через SQLx; миграции хранятся в `backend/migrations/`.
- Управление контейнерами выполняется через Docker Engine API; пользовательский ввод никогда не интерполируется в shell-команду.
- Preview-режим не требует Docker и не должен заявлять о запуске VPN.
- Host preflight выполняет только read-only проверки Linux-зависимостей; не создаёт интерфейсы и не изменяет маршруты.
- Runtime подключается через интерфейс `RuntimeAdapter`; HTTP-обработчики не должны зависеть от конкретной реализации Docker.

### Формат URI и подписки
- Планируемая сериализация: 4-байтовая big-endian длина несжатого содержимого + zlib deflate + URL-safe Base64 без padding.
- Подписки доступны через токенизированный endpoint `/sub/:token` с параметром `?format=amnezia|awg|ovpn`.
- Формат должен быть проверен по официальным клиентским fixtures до production.

### Хранение
- Настройки, хеш администратора, конфигурации контейнеров, ключи пиров, история трафика и аудит хранятся локально: SQLite в Docker volume.
- Перед обновлением контейнера автоматически создаётся резервная копия.

## 5. Модель данных

- **PanelAuth & Settings:** имя администратора, Argon2id password hash, базовый путь панели, SSL/домен, расписание обновлений и язык.
- **ProtocolContainers:** идентификатор, тип, image, статус, порт, транспорт, подсеть, DNS, MTU, ревизия конфигурации и параметры протокола.
- **AmneziaWG:** версия протокола, `Jc`, `Jmin`, `Jmax`, `S1–S4`, `H1–H4`, `I1–I5`, серверные ключи.
- **OpenVPN/Cloak:** cipher, флаг Cloak, server name, public key, admin UID, CA certificate и ta key.
- **Clients / Peers:** ID, имя, заметка/email, контейнер, enabled, IP, ключи, Cloak UID, subscription token, синхронизированная ревизия, лимит и счётчики трафика, срок доступа, handshake и дата создания.
- **UpdateJobs & AuditEvents:** история обновлений образов, ротации параметров и изменения ревизий.

## 6. Безопасность

- Первичная настройка администратора атомарна и доступна только один раз.
- Пароли хешируются и проверяются Argon2id.
- Секреты и приватные ключи не попадают в логи и frontend.
- Запрещено передавать пользовательский ввод в shell; использовать Docker API и строго типизированные параметры.
- API не выставлять наружу без TLS, ограничений доступа, надёжных секретов и проверки безопасности.
- Для чувствительных действий вести аудит.

## 7. Этапы реализации

1. Каркас монорепозитория, API health-check и базовый интерфейс.
2. Хранилище, первичная настройка администратора, сессии и настройки.
3. Runtime-адаптер preview и Docker, управление контейнерами.
4. Модель клиентов/пиров, генерация ключей и IP-адресов.
5. Экспорт конфигураций, QR и динамические подписки.
6. Настройки AmneziaWG DPI и проверка совместимости.
7. OpenVPN/Cloak.
8. Учёт трафика, квоты, сроки доступа и аудит.
9. Обновления Docker-образов с резервным копированием.
10. CLI, установщик VPS, Docker Compose, документация и тестирование.

## 8. Критерии готовности

- Чистая установка позволяет безопасно создать администратора.
- Preview работает без Docker и сохраняет состояние после перезапуска.
- Docker runtime не использует shell для пользовательских параметров.
- Конфигурации и URI принимаются официальными клиентами.
- Подписки отражают актуальную ревизию конфигурации.
- Обновления сохраняют данные пиров и имеют резервные копии.
- Установка и восстановление документированы; критические сценарии покрыты тестами.

Совместимость конфигураций с официальными клиентами должна быть подтверждена fixtures и интеграционными тестами до production.

# Технологический стек и архитектурные решения

## Решение

Backend проекта переведён с Express/TypeScript на **Rust**. Frontend остаётся на **React + TypeScript**.

Rust выбран для системного control plane: управление процессами и контейнерами, сетевые операции, работа с ключами и конфигурациями. Он даёт нативную производительность, статическую типизацию и контроль над конкурентностью. Переписывать браузерный UI на Rust нецелесообразно.

## Компоненты

| Область | Технология | Назначение |
|---|---|---|
| HTTP API | Axum | Маршруты и обработчики |
| Async runtime | Tokio | Асинхронный ввод-вывод и фоновые задачи |
| Database | SQLite + SQLx | Локальное постоянное хранилище |
| Password hashing | Argon2id | Хеширование пароля администратора |
| Sessions | Opaque random token + HttpOnly cookie | Сессии без хранения токена в открытом виде |
| Frontend | React + TypeScript + Vite | Панель управления |
| Container runtime | Docker Engine API/socket (планируется) | Изолированные VPN-сервисы |

## Границы первого релиза

1. Один локальный администратор.
2. Один узел панели; несколько VPN-контейнеров в дальнейшем.
3. SQLite для простого self-hosted развёртывания.
4. API по умолчанию слушает loopback.
5. Docker socket не подключается, пока не реализован отдельный ограниченный runtime adapter.

## Важные ограничения

- Rust сам по себе не делает приложение безопасным: необходимы аудит, тесты, лимиты запросов, CSRF-защита, безопасная работа с Docker socket и корректное управление секретами.
- SQLite подходит для первой версии панели на одном узле. При переходе к нескольким инстансам и конкурентной нагрузке пересмотрим хранилище.
- Никакие экспериментальные форматы Amnezia URI или ключи нельзя считать совместимыми до тестов с официальными клиентами.
